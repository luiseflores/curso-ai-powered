¿Qué es un MCP?

  • Model Context Protocol — le da al asistente acceso directo a herramientas y datos externos (bases de datos, APIs, documentación).
  • El asistente CONSULTA un MCP directamente — sin que vos copies/pegues información a mano en cada mensaje.
  • Cada MCP expone acciones específicas: ej. leer un ticket de Jira, correr una query de solo lectura.
  • Corre como proceso aparte — lo configurás una vez, el asistente lo usa cuando lo necesita.

MCP vs CLI

  • CLI: el asistente EJECUTA un programa como comando de terminal (acli, git).
  • MCP: el asistente CONSULTA un servidor directamente, sin pasar por la terminal.
  • Regla del curso: el CLI siempre va primero — Atlassian CLI antes que Atlassian MCP, Playwright CLI antes que Playwright MCP.
  • El MCP es respaldo/fallback — no reemplaza al CLI como camino principal.

¿Qué es un custom field y un workflow?

  • Un proyecto Jira se puede configurar, no solo usar: campos propios y estados propios.

Gotcha: acli necesita el ID numérico

  • acli (y la API de Jira) identifica cada custom field por ID numérico, no por su nombre visible.
  • No existe acli jira field list: no hay forma de listar campos por nombre.
  • No hay name-addressing: nunca se le pasa el nombre del campo, solo el ID.
  • Estrategia sin código: un ticket modelo, un ticket real con cada campo lleno, que después se inspecciona.
# lo que ves en la UI          # lo que entiende acli
Criterios de aceptación   →   customfield_10050   # ejemplo
sin name-addressing ticket modelo
gotcha14 / 18
